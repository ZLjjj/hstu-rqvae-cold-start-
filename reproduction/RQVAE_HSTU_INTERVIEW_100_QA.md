# RQ-VAE + HSTU 冷启动推荐项目：100 个面试问题与参考答案

> 适用方向：推荐算法、机器学习工程、搜索/召回、生成式推荐。建议先掌握第 1、5、18、49、63、68、70、83、89、90 题，再按模块扩展。

## 一、项目概述与业务价值（1—10）

### 1. 请用一分钟介绍这个项目。

参考答案：这个项目解决序列推荐中的物品冷启动问题。普通 HSTU 依赖可训练 Item ID embedding，新物品没有正向交互就缺少有效表示。我先用 MiniLM 和类别特征构造内容向量，再训练三层 RQ-VAE 得到层级 Semantic ID，并比较 Route A、旧简化 Route B 和 Full-Token Route B。Route A 把三级码本向量组合成物品 embedding，冷启动效果最好，cold HR@100 达到 0.1028；Full-Token Route B 把完整历史展开为语义 Token，明显改善了旧 Route B 的整体推荐质量，但 cold HR@100 仍只有 0.0018。

### 2. 这个项目要解决的核心业务问题是什么？

参考答案：核心问题是新物品在没有交互历史时无法通过 Item ID embedding 学到表示。例如新电影刚入库，传统协同过滤或序列模型很难把它排到前面。项目希望利用标题、类别等内容侧信息，为新物品生成可复用的语义表示，使模型在零正向交互条件下仍具备一定召回能力。

### 3. 整体架构分为哪几个阶段？

参考答案：第一阶段是内容编码，把电影标题通过 MiniLM 编成 384 维向量，再拼接 18 维类别特征。第二阶段是 RQ-VAE，把 402 维输入编码为 64 维隐变量并量化成三层 Semantic ID。第三阶段是 HSTU，对用户历史序列建模。第四阶段是检索：Route A 使用用户向量与物品语义向量做点积 Top-K；Route B 生成语义 Token，再映射回物品。

### 4. 为什么选择 RQ-VAE，而不是直接使用文本向量？

参考答案：选择 RQ-VAE 的首要动机不是预设它一定优于文本向量，而是验证层级离散表示能否提供共享码本结构，并支持向量检索与 Token 生成两种路线。当前 Route A 的 cold AUC=0.5920，高于 Dense 的 0.4757，但两组输入和结构并未完全匹配：Route A 使用文本加类别特征，Dense 主要使用文本向量。因此只能说本设置下观察到增益，不能把差异全部归因于离散化；更公平的实验应比较相同输入下的连续 RQ 编码器隐变量与离散码。

### 5. 项目最重要的实验结论是什么？

参考答案：结论有四点。第一，Route A 是冷启动效果最好的方案，cold HR@100 为 10.28%。第二，普通 HSTU 的整体头部效果最好，NDCG@100 为 0.2129，但冷 HR 完全为零。第三，旧 Route B 平均只有约 6.26 个唯一 Beam 候选。第四，Full-Token Route B 将整体 HR@100 从 0.2636 提升到 0.3788，并把 Beam 唯一物品提高到约 217.62 个，但 cold AUC 降到 0.0777，说明它主要改善暖物品建模，没有解决冷启动。

### 6. 五组核心对照实验分别是什么？

参考答案：第一组是普通 HSTU，使用独立可训练 Item ID embedding。第二组是 Dense baseline，使用冻结的 MiniLM 内容向量加可训练线性投影。第三组是 Route A，用冻结的三级 RQ-VAE 码本组合物品向量。第四组是旧简化 Route B，历史仍是物品级向量，只在输出端生成三码。第五组是 Full-Token Route B，把完整历史展开为 Semantic Token，并采用分层 next-token 训练、合法 Trie、自适应 Beam 和 Token 级 Exact Scorer。

### 7. 你在项目中的主要贡献是什么？

参考答案：我完成了 RQ-VAE 与 HSTU 的桥接、Route A、旧生成路线和 Full-Token 生成路线、严格冷启动数据过滤、物品外部 ID 对齐、全候选 AUC、冷启动分桶指标和语义码质量审计；同时修复了原 MRR 对未命中样本仍计入 1/(K+1) 的问题，并实现合法 Trie、自适应 Beam、前缀共享 Exact Scorer 以及训练和 GPU 资源记录。

### 8. 项目中最难的工程问题是什么？

参考答案：最难的是跨仓库物品 ID 对齐。RQ-VAE 原本可能使用连续内部索引，而 HSTU 使用 MovieLens 原始稀疏 ID，最大 ID 为 3952，但实际物品只有 3706 个。如果只按行号拼接，会把语义码分给错误电影。我保留外部 MovieLens ID，并导出显式的 item_id_to_codes 张量作为桥接协议。

### 9. 这个项目的创新点如何表述？

参考答案：创新点不应表述成发明了 RQ-VAE 或 HSTU，而是完成了面向严格物品冷启动的系统集成和对照验证：将层级 Semantic ID 以向量替换和 Token 生成两种方式接入 HSTU，并建立覆盖数据切分、桥接对齐、全候选评分、冷启动分桶和码本审计的一体化实验流程。

### 10. 如果面试官问项目是否达到生产可用，你怎么回答？

参考答案：目前更接近研究原型。Route A 证明了 Semantic ID 对冷启动有价值，但 cold HR@10 只有 0.73%，整体 NDCG@100 也低于普通 HSTU。生产化还需要独立测试集、多随机种子、更完整的内容覆盖、ID 与语义表示融合，以及高效候选索引和在线特征更新机制。

## 二、数据集与冷启动协议（11—20）

### 11. MovieLens-1M 在项目中有多少用户和物品？

参考答案：数据包含 6040 个用户、3706 个有交互电影和约 100 万条评分。物品使用原始 MovieLens ID，最大值为 3952，中间存在空缺，因此不能把最大 ID 误认为物品数量。

### 12. 用户序列如何构造？

参考答案：先按时间戳对每个用户的交互升序排列。训练时留出用户最后一次交互，并在此前序列中进行自回归下一物品训练；评估时使用最后一次交互作为目标，之前的交互作为历史。最大历史长度为 200，过长时保留最近的交互。

### 13. HSTU 的训练样本是如何生成的？

参考答案：每个用户在 DataLoader 中对应一条序列，但损失不是只监督一个目标。例如序列为 i1、i2、i3、i4，模型会用 i1 预测 i2，用 i1、i2 预测 i3，再用前三个预测 i4。这样一条用户序列会产生多个自回归监督位置。

### 14. 冷物品是如何选出的？

参考答案：从 3706 个有交互物品中，以固定种子 42 均匀抽取 10%，得到 371 个冷物品。四组实验都使用同一集合，划分还会写入 cold_start_split.json，保证可审计和可复现。

### 15. 为什么是 371 个冷物品，却有 545 个冷测试样本？

参考答案：371 是冷物品种类数，545 是最后一个目标属于冷物品的用户样本数。同一部冷电影可以成为多个用户的最后一次交互，因此测试样本数可以大于冷物品种类数。

### 16. “严格冷启动”在训练数据中是怎么实现的？

参考答案：先从每个用户序列中留出最后一次交互，然后删除剩余训练序列中的全部冷物品。如果过滤后不足两个交互，就删除该用户训练行。这样冷物品不会作为 HSTU 的正目标或历史输入出现。不过当前负采样仍可能抽到冷物品，这是协议中需要进一步修复的地方。

### 17. 四组实验的数据是否完全相同？

参考答案：HSTU 部分使用相同的用户、时间序列、371 个冷物品、545 个冷目标样本和候选物品集合。差异主要在物品表示、训练目标和检索方式。Route B 的输出目标从 item 变成了三级语义码，但用户历史和目标物品仍来自同一数据。

### 18. 当前验证集和测试集是如何划分的？有什么问题？

参考答案：当前 val_dataset 和 test_dataset 都设置 ignore_last_n=0，因此二者都使用每个用户最后一个物品作为目标，实际上是同一批样本。模型根据 val/ndcg@100 选择最佳 checkpoint，随后又在相同目标上报告 test，存在模型选择偏乐观。更规范的做法是倒数第二个交互做验证、最后一个交互做测试。

### 19. 候选物品集合是什么？

参考答案：候选集合来自数据模块中的全部 MovieLens 物品，大约 3706 个。推理时先屏蔽用户历史中已经交互过的物品，再从剩余候选中取 Top-200。训练时的 128 个负样本与测试时的 Top-200 是两个不同概念。

### 20. `zero` 和 `few` 分桶分别表示什么？

参考答案：zero 表示目标物品在模型可见训练交互中的计数为 0，属于严格冷启动；few 表示训练计数在 1 到 5 之间，属于长尾物品。本次实验是人为留出严格冷物品，因此主要关注 zero/cold 指标，few 指标全零不能直接解释为模型对长尾物品完全无效，也可能是该测试分桶没有样本。

## 三、内容编码与 RQ-VAE（21—35）

### 21. RQ-VAE 的输入特征是什么？

参考答案：电影标题使用本地 all-MiniLM-L6-v2 编码成 384 维文本向量，再拼接 18 维电影类型 one-hot 特征，形成 402 维输入。这样同时保留语义内容与结构化类别信息。

### 22. RQ-VAE 编码器的结构是什么？

参考答案：编码器是 MLP，维度从 402 依次经过 512、256、128，最终映射到 64 维隐空间。解码器使用反向隐藏层结构，将量化后的 64 维表示重建为 402 维内容特征。

### 23. 什么是残差量化？

参考答案：第一层码本近似原始隐向量 z，得到向量 e1；第二层不再量化 z，而是量化残差 z-e1；第三层继续量化前两层未解释的残差。因此 z 约等于 e1+e2+e3。前层学习粗粒度语义，后层逐步补充细节。

### 24. 为什么使用三层码本？

参考答案：单层码本容量有限，码本过大又会增加稀疏和训练困难。多层残差量化用多个中等规模码本组合出更大的表达空间，同时保持逐层结构。项目中每层 1024 个码，三层理论组合空间为 1024 的三次方，但实际只使用真实物品对应的少量组合。

### 25. 每个物品最终得到什么形式的语义 ID？

参考答案：每个物品得到一个三元组，例如 (17, 392, 81)。它不是普通的连续 Item ID，而是三层码本索引。相似物品可能共享第一层或前两层前缀，从而共享部分语义表示。

### 26. RQ-VAE 的训练目标是什么？

参考答案：总损失由内容重建损失和量化损失构成。文本连续特征使用平方重建误差，类别特征使用二元交叉熵；量化部分包含码本向编码器输出靠近的 embedding loss，以及带 commitment_weight 的编码器承诺损失。

### 27. commitment loss 有什么作用？

参考答案：它约束编码器输出不要频繁漂离所选码本向量。如果没有约束，编码器可能不断改变输出，码本追赶困难，量化结果不稳定。项目中 commitment_weight 为 0.25，用于平衡重建能力和离散化约束。

### 28. 为什么使用 K-Means 初始化？

参考答案：随机初始化码本时，一些码向量可能远离数据分布，早期很难被选中。K-Means 用首批隐向量初始化聚类中心，使码本从训练开始就覆盖实际数据区域，有助于提高利用率并减少死码。

### 29. EMA 码本更新是怎么做的？

参考答案：模型统计每个码被分配的样本数和对应隐向量之和，通过指数滑动平均更新 cluster size 与 embedding sum，再计算新的码本中心。EMA 模式下码本权重不直接通过普通梯度更新，可以降低离散分配带来的训练振荡。

### 30. 什么是死码？项目如何处理？

参考答案：死码是长期没有样本选择的码本向量，它会浪费容量并导致表示坍缩。项目根据 EMA cluster size 判断死码，并从当前批次隐向量中随机选取样本重置。最终审计中三层死码率均为 0。

### 31. 码本 perplexity 表示什么？

参考答案：perplexity 衡量码本使用分布的有效多样性。若所有样本只使用少数码，perplexity 会很低；使用越均匀，数值越接近码本大小 1024。本次三层 perplexity 分别约为 767.8、809.5 和 819.5，说明码本覆盖较充分。

### 32. 如何判断 RQ-VAE 是否发生码本坍缩？

参考答案：我会同时检查每层码本使用率、死码率、perplexity、完整语义码唯一率、最大重复比例和重建损失。本次每层使用率超过 98.6%、死码率为 0、完整码冲突率约 1.17%，因此没有明显坍缩。

### 33. 什么是语义码冲突？

参考答案：不同物品可能得到完全相同的三层语义码，这就是冲突。Route A 中它们仍可能因为上下文处理而有近似表示，但区分能力受限；Route B 中完整码映射回多个物品时，模型的 Token 概率无法区分这些物品。本次完整语义码冲突率约为 1.17%。

### 34. RQ-VAE 的物品训练/验证如何切分？

参考答案：沿用原预处理后先过滤评分次数少于 5 的电影，剩余 3416 个物品，再用固定种子 42 随机划分 80% 训练和 20% 验证；训练完成后为全部 3416 个合格物品导出语义码。这个 RQ-VAE 划分与 HSTU 的 371 个冷物品集合相互独立，因此部分 HSTU 冷物品可能参加过 RQ-VAE 内容训练。当前实验严格的是“无 HSTU 交互正例”，不是整条内容编码管线完全未见冷物品。

### 35. RQ-VAE 的覆盖率问题是什么？

参考答案：HSTU 候选物品有 3706 个，但 RQ-VAE 因“至少 5 条评分”过滤只覆盖 3416 个，整体 ID 空间覆盖率为 86.44%。371 个冷物品中有 338 个获得语义码，覆盖率 91.11%，仍有 33 个冷物品无法使用 Route A/B，这是冷启动效果的上限约束。

## 四、HSTU 序列模型（36—48）

### 36. HSTU 在项目中承担什么任务？

参考答案：HSTU 负责把用户按时间排列的历史物品 embedding 编码为上下文兴趣表示。训练时每个位置预测下一个物品，推理时取最后一个有效位置的输出作为当前用户向量，再用于向量检索或语义 Token 生成。

### 37. HSTU 和标准 Transformer 的主要区别是什么？

参考答案：这份实现使用 U、V、Q、K 联合投影和门控聚合结构，注意力权重采用 SiLU(QKᵀ+B)/N，而不是标准 softmax(QKᵀ/√d)。注意力结果归一化后与门控向量 U 做逐元素乘法，再经过输出投影和残差连接。

### 38. 为什么 HSTU 使用 SiLU 注意力而不是 softmax？

参考答案：SiLU 允许注意力权重保留更灵活的幅度和符号模式，不强制每一行归一化为概率分布；再除以序列长度控制尺度。它与门控结构结合，适合大规模稀疏行为序列。不过当前项目是复现版，没有使用论文中的全部高性能内核。

### 39. U、V、Q、K 分别有什么作用？

参考答案：Q 和 K 计算不同位置之间的相关性，V 提供被聚合的内容；U 是输入相关的门控信号。注意力聚合结果 a 经过归一化后，与 U 做 U⊙a，使模型能够按当前位置动态控制历史信息的写入强度。

### 40. 相对位置和时间偏置如何使用？

参考答案：模型在 QK 分数中加入相对位置偏置和分桶后的时间间隔偏置。位置偏置描述两个行为相隔多少步，时间偏置描述真实时间跨度，使模型能区分“连续观看”和“相隔很久的相似行为”。

### 41. 为什么需要因果 Mask？

参考答案：下一物品预测不能看到未来行为。因果 Mask 屏蔽当前位置之后的交互，使位置 t 的表示只能依赖 1 到 t 的历史，避免训练标签泄漏。

### 42. 什么是 Jagged Sequence？

参考答案：不同用户历史长度不同，如果全部补齐到 200，会产生大量无效计算。Jagged 表示把有效 token 连续存储，并用 offsets 标记每个用户的起止位置。实现中会在 Jagged 和 padded dense 之间转换，以兼顾计算效率和注意力操作。

### 43. HSTU 输入除了物品 embedding 还有什么？

参考答案：输入预处理器会加入可学习位置 embedding，并构造有效位置 Mask。序列载荷中还包含时间戳，供相对时间偏置模块使用。最终编码结果经过 L2Norm postprocessor，便于与归一化物品向量做点积检索。

### 44. HSTU 的训练损失是什么？

参考答案：Baseline、Dense 和 Route A 使用 sampled softmax。对每个有效位置，用户输出向量与正确下一物品计算正分数，并采样 128 个负物品计算负分数，再通过温度为 0.05 的 softmax 交叉熵优化。

### 45. 为什么训练不直接对全部物品做 Softmax？

参考答案：全物品 softmax 的计算和显存开销随物品数线性增长，在大规模目录中成本很高。负采样用少量候选近似分类目标。本项目 MovieLens 只有约 3706 个物品，但仍沿用可扩展的 128 负样本设置。

### 46. 负样本是怎样采的？

参考答案：LocalNegativesSampler 从 all_item_ids 中均匀随机采样，当前没有按热度或困难程度加权。若采到与正物品相同的 ID，会把对应 logit 屏蔽。需要注意 all_item_ids 包含预留冷物品，因此冷物品可能作为负例获得梯度。

### 47. 为什么物品向量要做 L2 归一化？

参考答案：归一化后点积主要反映方向相似度，避免模型仅通过增大 embedding 范数提高分数，也让不同表示来源的候选处于更一致的尺度。训练负样本和候选索引都会使用归一化向量。

### 48. HSTU 的当前主要配置是什么？

参考答案：物品和序列 embedding 维度为 50，使用 2 个 HSTU block、1 个 attention head，QK 和线性隐藏维度也为 50；线性 dropout 为 0.2，启用相对位置与时间偏置，最长历史 200，最终候选 Top-K 为 200。

## 五、Dense 与 Route A（49—58）

### 49. Dense baseline 的完整流程是什么？

参考答案：先离线导出每个物品的 MiniLM 384 维内容向量，构建按 MovieLens ID 对齐的 dense table；训练时冻结原始 dense table，只学习一个从 384 维到 50 维的线性投影，然后把投影结果作为 HSTU 的物品 embedding。检索时对全物品点积并取 Top-200。

### 50. 为什么 Dense baseline 是必要的？

参考答案：它用于区分“使用内容信息”与“使用离散 Semantic ID”两种收益。如果 Route A 只优于普通 ID baseline，却不优于 Dense，就不能说明残差量化和码本共享带来了额外价值。本次 Route A 的冷指标明显高于 Dense，因此支持 Semantic ID 的增益。

### 51. Route A 如何把语义码变成物品向量？

参考答案：对三层语义码分别查询对应层码本 embedding，得到三个 64 维向量；使用 concat_proj 时把它们拼成 192 维，再通过线性层投影到 HSTU 的 50 维空间。缺失语义码会查询 padding 行，因此投影输入为零；由于线性层含 bias，最终结果可能等于投影偏置，并不严格等于零向量。ID≤0 的无效位置才会在输出端显式清零。

### 52. 为什么 Route A 选择 concat_proj，而不是直接求和？

参考答案：三层码本承担不同粒度的残差语义，直接求和会混合层级角色。拼接后投影允许模型为不同层学习不同权重和跨层组合，同时还能适配 HSTU 的 50 维输入。求和更简单，但要求码本维度等于目标 embedding 维度。

### 53. Route A 为什么能推荐冷物品？

参考答案：冷物品虽然没有 HSTU 正向交互，但只要有标题和类别，就能通过 RQ-VAE 得到三级码，并共享已经学习好的码本向量。HSTU 学到的是用户兴趣与语义空间之间的匹配，而不只依赖某个独立 Item ID 的历史梯度。

### 54. Route A 为什么比 Dense 更好？

参考答案：一种解释是 RQ-VAE 的离散化起到了聚类和去噪作用，使相似物品共享稳定的语义原型；Dense 则保留完整文本差异，其中可能包含与推荐偏好无关的信息。实验中 Route A 的 cold HR@100 是 0.1028，Dense 为 0.0202，但这个结论仍需多随机种子验证。

### 55. 为什么冻结 RQ-VAE 码本？

参考答案：冻结可以保持 RQ-VAE 预训练语义空间稳定，避免 HSTU 的推荐损失破坏码本结构，也使实验更清楚地测量预训练 Semantic ID 的价值。代价是码本无法针对推荐目标适配，因此可训练码本是重要消融方向。

### 56. Route A 的训练目标是否直接优化冷指标？

参考答案：没有。Route A 仍使用普通的下一物品 sampled softmax，且冷物品不会作为正训练目标。它的冷启动能力来自码本共享和内容侧泛化，而不是直接看到冷标签，这正是实验希望验证的机制。

### 57. Route A 为什么整体 HR/NDCG 低于普通 HSTU？

参考答案：独立 ID embedding 能精确记忆热门和暖物品，而 Semantic ID 强制相似物品共享码本成分，可能损失同类物品之间的细粒度区分。此外码本被冻结、覆盖不完整，内容重建目标也不完全等价于推荐排序目标，因此冷启动增强伴随暖物品头部能力下降。

### 58. 如何改进 Route A 的冷暖权衡？

参考答案：这些是后续建议，当前最终 Route A 尚未实现冷暖融合。优先可测试 `v=v_ID+αv_semantic`：暖物品同时使用 ID 和语义表示，冷物品把不可靠的 ID 分支置零后退化为语义表示；还可加入热度门控或唯一 ID residual。仓库只预留了全部码本解冻配置，没有完成“只微调后两层”和语义结构正则的最终实验，因此面试中不能说这些方案已经验证。

## 六、旧简化 Route B 生成式检索（59—70）

### 59. Route B 的概率分解是什么？

参考答案：目标物品语义码为 (c1,c2,c3)，模型计算 p(c1|h)·p(c2|h,c1)·p(c3|h,c1,c2)。取对数后，完整物品路径分数是三层条件对数概率之和。h 是 HSTU 输出的用户上下文向量。

### 60. Route B 如何训练？

参考答案：对每个训练目标物品查出三级语义码。第一层用 h 预测 c1；预测下一层时，把真实前缀码 embedding 投影后加到上下文中，再预测 c2 和 c3。三层有效交叉熵取平均，属于 teacher forcing 训练。

### 61. Beam Search 在 Route B 中怎么工作？

参考答案：从空前缀开始，第一层扩展高概率 c1，第二层基于每条前缀扩展 c2，第三层再扩展 c3；每层候选按累计 log probability 排序，只保留 beam_size=8 的路径。最终完整码通过 code_to_items 映射回真实物品。

### 62. 什么是前缀约束？

参考答案：不是任意码组合都对应真实物品。项目预先统计真实物品出现过的一层、两层和三层前缀，Beam 扩展时只保留合法前缀，避免生成不存在的语义路径。它提高有效率，但也会限制搜索空间。

### 63. “全物品 Exact Scorer 补齐”是什么意思？

参考答案：如果 Beam 映射出的唯一有效物品不足 200，就对所有具有有效语义码的物品计算其完整路径分数 log p(c1|h)+log p(c2|h,c1)+log p(c3|h,c1,c2)，排除历史与重复物品后按分数补到 Top-200。“精确”指不再近似搜索，而是对每条已知物品路径准确评分。

### 64. Exact Scorer 和 cold AUC 有什么关系？

参考答案：二者使用相同的全物品 Token 概率，但用途不同。补齐只需要从全量排序中取够 Top-200；AUC 则需要知道正确目标在全部有效候选中的全局排名，所以必须保留全候选分数。

### 65. Route B 如何处理多个物品共享相同语义码？

参考答案：code_to_items 会把同一完整码映射到一个物品列表，这些物品获得相同 Token 路径分数。模型本身无法在它们之间进一步区分，只能依赖固定顺序或后续补充排序，因此语义码冲突会直接限制 item-level 排序能力。

### 66. 为什么 Beam 最后只有约 6.26 个唯一候选？

参考答案：beam_size 只有 8，最终最多保留少量完整路径；前缀约束会过滤非法扩展，用户历史过滤会删除已看物品，多个路径或码冲突还可能产生重复。最终测试中平均 unique_before_fill 仅 6.26，说明 Beam 对 Top-200 召回覆盖严重不足。

### 67. Route B 为什么训练和推理都更慢？

参考答案：训练需要逐层计算三个码本分类头；验证和测试不仅要逐用户做 Python 级 Beam 展开，还要为大量物品计算条件 Token 概率。当前没有高效 Beam kernel，Route B 训练约 4 小时 15 分钟，明显慢于 Route A 的约 48 分钟。

### 68. 旧简化 Route B 的实验结果为什么较差？

参考答案：主要原因包括三级预测误差累积、teacher forcing 与推理解码不一致、Beam 过窄、语义码冲突、前缀约束导致候选收缩，以及 RQ-VAE 内容重建码并不一定是最佳生成目标。其 cold AUC 只有 0.2289，说明不仅 Beam 覆盖不足，全量 Token 概率排序本身也偏弱。

### 69. cold HR@10、50、100、200 为什么完全相同？

参考答案：Route B 四个 cold HR 都约为 0.001835，结合 545 个冷测试样本，意味着大约只有一个冷目标进入 Top-200，而且它已经位于 Top-10；排名 11 到 200 之间没有新增冷命中。这是解码能力严重不足的直接信号。

### 70. 如何改进 Route B？

参考答案：可以扩大并动态调整 Beam、采用 trie 上的批量 GPU 解码、加入 item disambiguation residual、使用推荐损失联合优化 Semantic ID、采用 sequence-level 或 listwise loss、减轻 teacher forcing 暴露偏差，并把生成模型用于粗召回后接轻量精排。本项目随后实现了完整历史 Token 化和合法子码优先的自适应 Beam，整体 HR@100 明显提高，但冷指标没有改善，说明搜索与序列形式并不是唯一瓶颈。

## 七、评价指标与结果解读（71—82）

### 71. HR@K 如何计算？

参考答案：每个用户只有一个正确目标。如果目标出现在推荐 Top-K 中，该样本记为 1，否则为 0，最后对全部用户取平均。HR@100=0.1028 表示约 10.28% 的对应样本目标进入了前 100。

### 72. NDCG@K 和 HR@K 有什么区别？

参考答案：HR 只关心是否命中，不区分第 1 名还是第 K 名；单目标 NDCG 会按 1/log2(rank+1) 给更靠前的命中更高权重。因此两个模型 HR 相同，目标排名更靠前的模型 NDCG 更高。

### 73. MRR 如何计算？

参考答案：MRR 是正确目标排名倒数的均值，即 mean(1/rank)，特别强调前几名。第 1 名贡献 1，第 10 名贡献 0.1，第 100 名只有 0.01，因此它比 AUC 更关注用户实际看到的头部结果。

### 74. 原项目的 MRR 有什么问题？

参考答案：代码把目标拼到 Top-200 结果末尾再查排名，所以未命中样本被当作第 201 名，仍获得 1/201≈0.004975。修正 MRR 应当让 Top-K 未命中贡献 0。本次同时保留旧 MRR用于对照，并新增 mrr_corrected。

### 75. 项目中的 AUC 如何计算？

参考答案：先给全候选物品打分，得到正确目标的全局排名 r 和有效候选数 N，再计算 (N-r)/(N-1)。它等价于正确目标击败随机负物品的比例；第 1 名为 1，最后一名为 0，中间位置约为 0.5。

### 76. cold AUC 是全局排序还是 Top-200 排序？

参考答案：是排除用户历史后的全局候选排序，不是只在 Top-200 内计算。Baseline、Dense 和 Route A 用用户向量与所有候选向量点积；Route B 用所有有效语义码物品的完整 Token 对数概率。

### 77. 为什么全体 AUC 上升，HR 却下降？

参考答案：AUC近似线性反映全局百分位，HR只判断是否跨过 Top-K 阈值。Route A 可能把大量目标从第 3000 名提高到第 500 名，显著提升 AUC却不增加 HR@100；同时一些暖目标从第 80 名掉到第 120 名，AUC只小幅下降，但 HR@100 会从 1 变成 0。

### 78. 为什么 Baseline 的 cold AUC 只有约 0.088？

参考答案：冷物品没有正向训练，但负采样池仍包含它们，因此它们可能被反复作为负例推离用户兴趣向量；同时暖物品得到大量正向训练。结果不是随机未训练的约 0.5，而是冷物品被系统性排到全局尾部。

### 79. 为什么 Dense 的 AUC 高于 Baseline，但 HR 更低？

参考答案：Dense 内容向量能让大量目标避免排在特别后面，因此改善全局百分位；但它对具体暖物品的记忆不如独立 ID embedding，难以把正确物品推入非常靠前的位置。所以 AUC 从 0.8240 升到 0.8472，HR@100 却从 0.5831 降到 0.4613。

### 80. 如何正确解读 Route A 的 cold AUC=0.592？

参考答案：它表示冷目标平均击败约 59.2% 的有效候选，比随机期望 0.5 高 9.2 个百分点，说明全局排序有一定改善；等价地看，目标仍大致处于从高到低约 40.8% 的位置，离头部很远。更贴近推荐体验的 cold HR@10 只有 0.73%、cold HR@100 为 10.28%，因此不能用 AUC=0.592 宣称冷启动已经解决。

### 81. Top-200 候选是随机抽取的吗？

参考答案：不是。Baseline、Dense 和 Route A 都对全物品计算分数，屏蔽用户历史，再选择分数最高的 200 个。Route B 先用 Beam 找候选，不足部分再用全物品 Exact Scorer 补齐。随机采样 128 个负例只发生在训练损失中。

### 82. AUC、HR、NDCG、MRR 应该优先看哪个？

参考答案：取决于业务目标。AUC适合观察全局排序和召回潜力；HR反映目标是否进入展示集合；NDCG和MRR更关注头部顺序。这个项目以冷启动召回为目标，应同时报告 cold AUC、cold HR@K 和 cold NDCG/MRR，不能只挑最高的 AUC。

## 八、工程实现与复现（83—90）

### 83. RQ-VAE 与 HSTU 之间的桥接文件包含什么？

参考答案：核心字段是 item_id_to_codes 和 codebook_vectors。前者按外部 MovieLens ID 存储每个物品的三级码，后者保存三层码本向量；metadata 记录层数、码本大小等配置，还可包含 cold mask。HSTU 加载时会校验维度和码范围。

### 84. 如何保证实验可复现？

参考答案：固定数据冷划分和模型随机种子为 42；持久化 cold item 列表；保存 Hydra 完整配置、代码提交哈希、训练命令、环境依赖、逐轮 metrics、最佳 checkpoint 和 RQ-VAE 审计 JSON；四组实验使用同一数据与候选集合。

### 85. 为什么使用 Hydra 和 PyTorch Lightning？

参考答案：Hydra 便于通过配置组合替换 embedding、模型路线、优化器和数据协议，减少硬编码；Lightning 统一训练、验证、测试、日志、checkpoint 和设备管理。代价是配置继承较复杂，排查最终生效参数时必须保存完整 resolved config。

### 86. 最佳 checkpoint 如何选择？

参考答案：训练最少 10 轮、最多 500 轮，以 val/ndcg@100 为监控指标，ReduceLROnPlateau 调整学习率，早停 patience 为 20。最终 Baseline、Dense、Route A、Route B 的最佳 epoch 分别为 87、171、135 和 58。

### 87. 资源消耗如何？

参考答案：RQ-VAE 训练 50,000 steps 约 6 分 50 秒；最初四组 HSTU 合计约 6 小时 38 分钟，显存峰值约 19.7GB。后续 Full-Token 加速版在 RTX 4090 D、BF16 和 FBGEMM GPU 环境中运行约 5 小时 29 分，采样峰值显存约 4.7GB。两次运行的硬件、验证频率和实现不同，因此墙钟时间不能直接做严格速度对比。

### 88. 缺少 FBGEMM 对实验有什么影响？

参考答案：项目检测不到可选 FBGEMM GPU jagged 算子时，会退回 PyTorch 实现，所以结果逻辑仍正确，但速度低于优化环境。它主要影响性能，不应被解释为 Route A/B 指标差异的原因，因为四组使用同一 fallback 环境。

### 89. 你如何做 RQ-VAE 质量审计？

参考答案：从训练 metrics 和 bridge artifact 统计每层使用率、死码率、perplexity、最大码重复比例、完整码冲突率、重建损失、全局物品覆盖率与冷物品覆盖率，并输出 PASS/FAIL JSON。审计避免在码本已经坍缩的情况下误把下游问题归因于 HSTU。

### 90. 如何验证实现没有物品 ID 错位？

参考答案：保留原始 external_item_ids，导出时按最大外部 ID 建表；加载后检查 item_to_codes 行数、有效码范围、码本层数和 size；随机抽取电影 ID，联合核对标题、dense 向量和语义码；测试中还加入缺失 ID、越界 ID 和桥接维度不一致的单元测试。

## 九、实验缺陷与严谨性追问（91—96）

### 91. 你认为当前实验最大的缺陷是什么？

参考答案：最大的缺陷是验证集与测试集实际上使用相同的最后交互目标，最佳 checkpoint 的选择已经间接利用最终测试样本，会造成乐观偏差。下一版应使用每个用户倒数第二个交互做验证、最后一个做测试，或使用全局时间切分。

### 92. 冷物品参与负采样为什么是问题？

参考答案：严格 item cold-start 通常要求训练阶段完全不知道这些物品的交互身份。当前冷物品虽然不作正例和历史，却可能作为负例获得梯度，特别不利于独立 ID baseline，并把 cold AUC 压到 0.088。它不会否定 Route A 相比 Dense 的观察，但可能夸大相对普通 Baseline 的收益。

### 93. 如何修复负采样协议？

参考答案：训练时为 LocalNegativesSampler 单独构建 warm_item_ids，只从非冷物品采负例；同时审计冷物品在正例、历史和负例中的出现次数必须全部为零。评估候选集仍包含冷物品，才能测试真正的零训练可见性。

### 94. 单随机种子有什么风险？

参考答案：冷物品集合、模型初始化和负采样都会带来方差。Route A 相比 Dense 的倍数提升建立在一个种子上，无法判断稳定性。至少应运行 3 到 5 个种子，报告均值、标准差和配对置信区间，必要时对用户级指标做 bootstrap。

### 95. RQ-VAE 过滤低频物品是否合理？

参考答案：对训练稳定性有帮助，但与冷启动目标存在冲突，因为最需要内容泛化的低频物品反而被排除。更合理的做法是从完整 movies.dat 元数据为全部物品生成内容向量，RQ-VAE 训练可使用全部内容；交互次数只用于评估分桶，不应决定是否拥有语义码。

### 96. 当前实验能否证明 Route A 一定优于 Dense？

参考答案：只能说在当前 MovieLens-1M、固定划分、单种子和现有超参数下，Route A 明显优于 Dense 的冷指标。要形成更强结论，还需要多种子、独立测试集、相同覆盖率、参数量与调参预算控制，以及在更大数据集上的验证。

## 十、优化方案与开放性问题（97—100）

### 97. 下一步最值得做的三个实验是什么？

参考答案：第一，修复验证/测试切分和冷物品负采样后重跑四组。第二，测试 ID+Semantic 混合 embedding，包括固定权重和热度门控。第三，运行 3 到 5 个随机种子并提高 RQ-VAE 对全部物品的覆盖率。这三项比继续扩大 Route B Beam 更优先。

### 98. 如果做线上系统，你会怎样设计？

参考答案：离线侧定期用物品元数据生成 dense 特征和 Semantic ID，构建版本化 bridge；在线用户行为经过 HSTU 或增量缓存得到兴趣向量。暖物品使用 ID+Semantic 融合向量，冷物品使用 Semantic 向量；先通过 ANN 粗召回，再结合热度、业务规则和精排模型输出结果，并监控冷物品曝光与点击。

### 99. 如何把这个项目扩展到更大数据集？

参考答案：数据上使用 Amazon 或工业日志并采用全局时间切分；模型上增加 HSTU 容量和分布式训练；检索上将暴力全物品点积替换为 FAISS/ScaNN 等 ANN；RQ-VAE 使用分布式 K-Means、批量编码和版本化码本；Route B 若保留，应使用批量 trie 解码和 GPU kernel。

### 100. 最终如何评价这个项目？
